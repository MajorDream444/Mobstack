# MobStack

MobStack is the execution rail for HAMAL-governed, MAIM-informed agent work.

It converts approved context and playbooks into portable workflows across Claude Code, Claude Cowork, Codex, Google AI Studio, and future hosts without allowing any host to become the source of truth.

## Status

**Stage A — Foundation (PROPOSAL)**

This repository defines contracts, schemas, adapters, gates, and example workloads. It does not authorize autonomous execution, production integrations, deposits, financial activity, external communications, or unsupervised publication.

## System boundary

- **MAIM** develops the builder: confidence, context, direction, experimentation, AI literacy, and ownership mindset.
- **HAMAL MOB PLAYBOOKS** owns operating doctrine, playbooks, SOPs, rubrics, MOBS, and industry patterns.
- **MobStack** loads approved doctrine, routes work, applies gates, creates handoffs, and emits receipts.
- **Industry OS repositories** own field evidence, claims, decisions, counterparties, and implementation code.
- **GitHub** is the canonical versioned record. Chat and AI tools are work surfaces.

Authority flows downward. Field evidence flows upward only as reviewed proposals.

## Foundation contents

- schemas — portable contracts for agents, MOBS, skills, gates, handoffs, and receipts
- adapters — host responsibilities and boundaries
- workflows — approved execution sequences
- gates — truth, language, authority, capital, and ownership safeguards
- examples — read-only industry workload mappings
- tests — contract fixtures and safety cases

## First workload

The West African Mobility OS is the first canary workload. MobStack references it; it does not copy or redefine its claims or decisions.

## Non-negotiables

No orphan outputs. No anonymous tools. No agent without a MOB. No workflow without a playbook. No memory without a source. No automation without safety boundaries. No machine passes a human gate.
